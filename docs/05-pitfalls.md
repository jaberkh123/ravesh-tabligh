# ۵. گورستان باگ‌ها — ۹ درس از میدان واقعی

> این فایل باارزش‌ترین بخش ریپوست: هر بند یک باگ واقعی است که در پروژهٔ «شهر سودوکو» رخ داد،
> ریشه‌یابی شد و فیکس شد. اگر به مشکلی خوردی، اول اینجا را بگرد.

## باگ ۱ — «هیچ تبلیغی نمایش داده نمی‌شود» (باگ تاریخی پروژه)

**علامت:** ۴ آیکون در پنل فعال بود، سرور با curl جواب سالم می‌داد، ولی اپ هیچ بنری نشان نمی‌داد.
**ریشه:** اپ درست همان لحظه‌ای که سرور آپدیت شده بود یک fetch زده و پاسخِ آن روز را گرفته بود →
state = Hidden. کد قدیمی برای حالت خطا/خالی هم قرار بود تا پایان `next_slot_in` (~۲ ساعت!) صبر کند.
**فیکس (دوبخشی):**
1. جدول retry هوشمند: خطای شبکه ۵ دقیقه، خطای API ۱۵ دقیقه، **لیست خالی فقط ۲ دقیقه**، موفق = سرور.
2. `onAppForegrounded()` در `onResume` — بنر Hidden با برگشت به اپ فوری دوباره fetch می‌کند (با گارد ۶۰s).
**درس:** «بنر نمی‌آید» اول تایمرهای خودت را چک کن، بعد سرور را.

## باگ ۲ — فرمت قدیمی سرور همه‌چیز را خالی می‌کرد

سرور یک دوره فرمت تک‌بنری (فیلدهای سطح‌بالا) داشت؛ اپ منتظر آرایهٔ `icons[]` بود.
**فیکس:** پارس دوگانه در `parseIcons` — آرایه نبود، فیلدهای تکی را به‌عنوان یک آیتم بپذیر؛
همچنین نام‌های دوتایی فیلدها (`icons_ratio`/`ratio`، `icons_next_slot_in`/`next_slot_in`).
**درس:** با هر تغییر سرور، backward-compat در پارس را نگه دار.

## باگ ۳ — عنوان‌های «؟؟؟؟» زیر آیکون‌ها

ردیف‌های قدیمی دیتابیس، عنوان خالی داشتند و UI «؟؟؟؟»/جای خالی نشان می‌داد.
**فیکس سمت اپ ممکن نیست** — مالک باید در پنل عناوین را پر کند. اپ فقط خالی بودن را تحمل می‌کند
(اگر خالی، متن رندر نمی‌شود).
**درس:** بعضی باگ‌ها «باگ پنل» هستند؛ برایشان کد ننویس، به مالک دستور بده.

## باگ ۴ — سایز APK بعد از تغییر کد دقیقاً یکسان ماند!

بعد از یک تغییر UI، سایز APK بایت‌به‌بایت با قبل برابر بود → تردید که کد جدید اصلاً داخل بیلد هست یا نه.
**فیکس تشخیص:**
```bash
unzip -p app/build/outputs/apk/release/app-release.apk classes*.dex | strings | grep -c ClassName
```
۱۷ رفرنس پیدا شد → کد داخل بود؛ سایزِ یکسان صادفهٔ فشرده‌سازی بوده.
**درس:** به سایز/mtime اعتماد نکن — محتوای dex را اثبات کن.

## باگ ۵ — ارور نصب APK: «Failed to collect certificates … null array»

اول فکر شد فایل خراب است یا امضا ناقص؛ checksum فایل گیت با محلی یکی بود → **فایل سالم،
دانلود کاربر ناقص بود.** (همچنین برای سازگاری نصب روی امولاتور، امضای v1+v2+v3 کمک می‌کند.)
**درس:** قبل از blame کردن بیلد، checksum بگیر؛ مشکل انتقال فایل رایج‌تر از چیزی است که فکر می‌کنی.

## باگ ۶ — raw.githubusercontent.com بعد از push موقتاً 404

بعد از push، لینک خام APK موقتاً 404 داد؛ API گیت فایل را با سایز درست نشان می‌داد و
`git hash-object` محلی = sha سرور بود. یعنی فایل روی گیت سالم است و فقط CDN/شبکه در راه است.
**درس:** برای اثبات وجود فایل از `api.github.com` + مقایسهٔ git-sha استفاده کن؛ raw ممکن است
تأخیر/فیلترینگ داشته باشد (به‌خصوص برای کاربران ایران).

## باگ ۷ — exit کد دروغگو بعد از pipe

`./gradlew assembleRelease | tail -20; echo $?` → کدِ خروجِ **tail** را می‌دهد نه gradlew را؛
یک بار بیلدِ خطادار «موفق» به نظر رسید.
**فیکس:** چک با متن خروجی: `... | grep -E "BUILD (SUCCESSFUL|FAILED)"` یا `set -o pipefail`.
**درس:** بعد از هر pipe، مفهوم `$?` را عوض نکن.

## باگ ۸ — برداشت اشتباه از «نمایش رندوم»

مالک گفت «چیدمان بنرها رندوم باشد». نسخهٔ اول: بنر تک‌آیتمی چرخان با انتخاب رندوم هر ۵ ثانیه.
اصلاح مالک: منظور **ترتیب رندوم آیکون‌ها در ردیف** بود («یک بار جدول بزرگسال اول، بار بعد یکی دیگر»).
**فیکس:** `shuffled()` روی ردیف + حذف بنر چرخان.
**درس:** قبل از پیاده‌سازی تفسیرت را در یک جمله تأیید کن.

## باگ ۹ — برداشت اشتباه از «آیکون را کوچک‌تر کن»

مالک گفت «آیکون را کوچک‌تر کن در صفحهٔ اول». نسخهٔ اول: آیکون‌های **تبلیغ** کوچک شدند (۷۰٪ سلول)!
اصلاح مالک: منظور **آیکون اصلی اپ** (جدول تزئینی) بود تا تبلیغ قشنگ جا شود؛ آیکون‌های تبلیغ باید
**بزرگ‌تر** می‌شدند (۹۰٪).
**فیکس:** آیکون اصلی ۴۸→۳۶dp و آیکون تبلیغ ۷۰٪→۹۰٪.
**درس:** ضمایر مبهم در درخواست‌های UI = خطر؛ «کدام آیکون؟» را اول بپرس.

## باگ ۱۰ — تبلیغ کافه‌بازار به‌جای اپ بازار، در مرورگر باز می‌شد

`click_url` (لینک شمارنده) با `Intent.ACTION_VIEW` و **بدون** `setPackage` باز می‌شد؛ بعد از
ریدایرکت سرور، مرورگر روی صفحهٔ وب `cafebazaar.ir/app/…` می‌ماند — نه اپ بازار باز می‌شد، نه
دانلودی شروع می‌شد؛ بعضی وقت هم انتخابگر «باز کردن با» می‌آمد.
**فیکس (دوطرفه — سرور + اپ):**
- سرور: فیلدهای `destination` + `package_name` در پاسخ API (پنل: فقط اسم پکیج) + پشتیبانی
  `via=app` در `click.php` (شمارش کلیک با پاسخ 204، بدون ریدایرکت).
- اپ: تپِ تبلیغ بازار = گزارش کلیک با `via=app` در پس‌زمینه + باز کردن مستقیم
  `bazaar://details?id=<pkg>` با `setPackage("com.farsitel.bazaar")`؛ اگر بازار نصب نبود →
  صفحهٔ وب بازار (fallback).
**درس:** لینک وب هرگز نمی‌تواند تضمین کند اپ مقصد باز شود؛ برای باز شدن اپ باید scheme اختصاصی
(`bazaar://details?id=`) + `setPackage` داد و آمار را جداگانه در پس‌زمینه گزارش کرد.

## باگ ۱۱ — اسکرول بنر: آیکون‌ها «آروم میان» و با برگشت دوباره «غیب و ظاهر می‌شوند» 🆕

علامت (واقعی، از کاربر): «اسکرول می‌کنم به راست، تبلیغ‌ها آروم میان؛ بعد اسکرول می‌کنم به چپ،
آیکون‌ها دوباره می‌خواهند لود بشن! در صورتی که لود شده — یک‌بار که لود شدند دیگر لازم نیست در
اسکرول هی از نو غیب و ظاهر بشن.»

**ریشه:** انیمیشن ورود پلکانیِ هر آیکون داخل خود آیتمِ `LazyRow` نوشته شده بود:
`remember { Animatable(0f) }` + `LaunchedEffect { snapTo(0); delay(index×۱ثانیه); fade-in }`.
اما `LazyRow` آیتم‌های خارج از دید را **dispose** می‌کند و با ورود مجدد از نو **compose** می‌کند:
- اسکرول به راست → آیتم تازه وارد compose می‌شود → انیمیشن از صفر شروع می‌شود →
  آیکونِ اندیس ۵ باید **۵ ثانیه** صبر کند تا ظاهر شود ⇒ «آروم می‌آیند».
- اسکرول به چپ → آیتمی که قبلاً دیده شده بود، از نو compose می‌شود → `remember` تازه
  ساخته می‌شود → alpha دوباره از ۰ شروع می‌شود ⇒ «غیب و ظاهر شدن مجدد / لود دوباره».
(خود تصویر از کش Coil می‌آمد و سریع بود؛ چیزی که کاربر می‌دید «رفتار لود دوباره»ی
ناشی از alpha بود — ولی تجربهٔ کاربر همان لود دوباره است و باید حل می‌شد.)

**فیکس (v2 — انیمیشن فقط یک‌بار):**
- وضعیت «دیده‌شده» هر آیکون به سطح **بنر** منتقل شد:
  `val appearedSlots = remember(st.icons) { mutableStateSetOf<Int>() }` — این مجموعه در
  طول عمر بنر زنده می‌ماند و مثل آیتم‌ها dispose نمی‌شود.
- هر آیکون یک‌بار که انیمیشنش شروع شد، همان لحظه در `appearedSlots` علامت می‌خورد؛
  دفعات بعد (هر اسکرولی) `alreadyShown=true` ⇒ `snapTo(1f)` بدون هیچ انیمیشنی.
- ورود پلکانی ۱ثانیه‌ای فقط برای **۳ آیکون پنجرهٔ اول** (قانون جلب توجه)؛ آیکون‌های
  بیرون از پنجره فقط بار اول با فید کوتاه (۲۵۰ms) وارد می‌شوند، نه با تاخیر index×۱ثانیه.
- تصویر با `ImageRequest` دارای `memoryCacheKey` ثابت (بر اساس slot) و
  `crossfade(false)` لود می‌شود تا خود Coil هم هیچ‌گاه دوباره‌سازی بصری نسازد.
- با refresh واقعیِ داده از سرور (لیست جدید)، مجموعه عمداً ریست می‌شود تا ورود پلکانی
  طبق قانون ۷ دوباره پخش شود — این رفتار باگ نیست، طراحی است.

**درس:** انیمیشنِ «یک‌بار در هر صفحه» را هرگز داخل آیتمِ Lazy ننویس؛ وضعیتش را بالاتر
(سطح بنر) نگه دار. `remember` داخل آیتمِ Lazy یعنی «یک‌بار در هر compose» — و compose
در لیست‌های Lazy بارها تکرار می‌شود.

## الگوی ریشه‌یابی که در همهٔ این‌ها جواب داد

1. **علامت را دقیق بنویس** (چه چیزی، کجا، از کِی).
2. **سمت سرور را با curl جدا کن** — اگر curl سالم است، مشکل در اپ است و برعکس.
3. **فایل را با checksum/sha اثبات کن** — نه سایز، نه ظاهر.
4. **لوگ فیلدهای تصمیم‌گیر** (`Log.d(TAG, ...)`) — state machine بدون لاگ، جعبهٔ سیاه است.
5. **فیکس دوطرفه:** ریشهٔ مشکل (تایمر) + نجات‌دهندهٔ کاربر (foreground refresh).
