# ۳. UI بنر — چیدمان، رندوم، انیمیشن پلکانی

> کد کامل واقعی: [`reference-code/AdBanner.kt`](../reference-code/AdBanner.kt)
> همهٔ اعداد اینجا از بازخوردهای واقعی کاربرِ اپ «شهر سودوکو» نهایی شده‌اند.

## ۳.۱ اصول چیدمان — AdIconsBanner

1. **دقیقاً ۳ آیکون در عرض صفحه** — عرض هر سلول:
   ```kotlin
   itemWidth = ((maxWidth - hPad * 2) - spacing * 2) / 3
   ```
2. **سرریز به راست اسکرول می‌خورد** — اگر آیکون‌ها > ۳ باشند (مثلاً ۴ تا)، چهارمی با اسکرول
   افقی از سمت راست می‌آید. برای اینکه جهت اسکرول مستقل از زبان دستگاه همیشه درست باشد،
   ردیف داخل `LocalLayoutDirection provides LayoutDirection.Ltr` قرار می‌گیرد.
3. **آیکون = ۹۰٪ عرض سلول** (`fillMaxWidth(0.9f)`) — بزرگ دیده شود تا کلیک بخورد.
   *(نسخهٔ اول ۱۰۰٪ بود، یک دوره ۷۰٪ شد به اشتباه، و با بازخورد کاربر به ۹۰٪ نهایی شد.)*
4. **نسبت تصویر از سرور** — `icons_ratio` («1:1» یا «9:3») با `adRatioToAspect` به float تبدیل و
   روی `aspectRatio(aspect)` اعمال می‌شود؛ پس هر شکلی که مالک در پنل بدهد، اپ همان را رندر می‌کند.
5. **کارت با سربرگ «پیشنهاد ما»** — پس‌زمینه و بوردر با alpha کم، هم در دارک هم لایت.
6. **تپ روی هر آیکون → `AdManager.openAd(ctx, icon.clickUrl)`** — همان آیکونِ خودش.

## ۳.۲ چیدمان رندوم ⭐

```kotlin
val displayIcons = remember(st.icons) { st.icons.shuffled() }
```

- `st.icons` (لیست اصلی) هر بار که سرور refresh می‌شود، نمونهٔ جدید است → کلیدِ `remember` عوض می‌شود
  → **شافل تازه**.
- هر بار که کاربر وارد صفحه می‌شود، کامپوزابل دوباره ساخته می‌شود → شافل تازه.
- نتیجهٔ کاربردی (خواستهٔ صریح کاربر): «یک بار اولِ ردیف جدول بزرگسال است، بار بعد ترتیب دیگری است.»

> ⚠️ درس تجربی: «نمایش رندوم» دو برداشت دارد — (۱) انتخاب تک‌آیتمِ رندوم در یک بنر چرخان،
> (۲) ترتیب رندومِ ردیف آیکون‌ها. منظور کاربر (۲) بود. پیش از پیاده‌سازی، از کاربر بپرس/مطمئن شو.

## ۳.۳ انیمیشن ورود پلکانی ⭐ (جلب توجه به تبلیغ)

هر بار صفحه لود می‌شود، آیکون‌ها **از چپ به راست**، هر کدام **۱ ثانیه بعد از قبلی**، با
fade-in نرم (~۰٫۷ ثانیه) ظاهر می‌شوند. کد کامل در `IconAdItem`:

```kotlin
val appearAlpha = remember { Animatable(0f) }
LaunchedEffect(reloadKey, icon.slot) {
    appearAlpha.snapTo(0f)
    delay(appearIndex * 1_000L)           // آیکون n → n ثانیه بعد از لود صفحه
    appearAlpha.animateTo(1f, tween(700)) // fade-in نرم
}
Column(modifier = Modifier
    .graphicsLayer { alpha = appearAlpha.value }   // بدون recomposition
    ...
)
```

نکات فنی مهم:
- `reloadKey = st.icons` — وقتی لیست تبلیغ refresh شود، `LaunchedEffect` با کلید جدید دوباره
  اجرا می‌شود: `snapTo(0)` → انیمیشن از نو پخش می‌شود (با ترتیب شافل جدید).
- `appearIndex` از `itemsIndexed` می‌آید — چون ردیف LTR است، اندیس ۰ = چپ‌ترین آیکون.
- انیمیشن روی `graphicsLayer { alpha }` است — **بدون recomposition**، روان.
- چون **همهٔ صفحات** از همین کامپوننت مشترک استفاده می‌کنند، انیمیشن همه‌جا فعال است.

## ۳.۴ بنر یکسان در همهٔ صفحات ⭐

تصمیم نهایی کاربر: تبلیغ در صفحهٔ خانه، انتخاب سختی و انتخاب مرحله باید **دقیقاً یک شکل** باشد.
پس فقط یک کامپوننت (`AdIconsBanner`) وجود دارد و بنرهای دیگر (مثل بنر تک‌آیتمی چرخان
`RotatingAdBanner` که یک دوره استفاده شد) حذف شدند.

مزایا:
- یک رفتار، یک باگ‌محل، یک انیمیشن — نگهداری ساده.
- کاربر هر صفحه‌ای که باشد، تبلیغ «همان شکل آشنا» را می‌بیند.

## ۳.۵ واکنش‌گرایی — اسکیل سراسری

در ریشهٔ اپ (`AppContent`)، Density سراسری بر اساس عرض صفحه مقیاس می‌شود:

```kotlin
val configuration = LocalConfiguration.current
val density = LocalDensity.current
val responsiveScale = (configuration.screenWidthDp / 400f).coerceIn(0.75f, 1.6f)

CompositionLocalProvider(
    LocalDensity provides Density(
        density.density * responsiveScale,
        fontScale = density.fontScale
    )
) { /* کل اپ */ }
```

- روی صفحهٔ باریک همه‌چیز (از جمله بنر) کوچک‌تر و روی تبلت بزرگ‌تر دیده می‌شود.
- `fontScale` دست‌نخورده می‌ماند تا تنظیمات دسترسی‌پذیری کاربر پایمال نشود.
- نتیجه: دکمه‌ها و بنرها «متناسب با اندازهٔ صفحه» — دقیقاً خواستهٔ کاربر.

## ۳.۶ جا باز کردن برای تبلیغ — عناصر اپ را فدا نکن، کوچک کن ⭐

تجربهٔ واقعی: بنر تبلیغ در صفحهٔ خانه زیر جدول تزئینی ۳×۳ بود و «قشنگ جا نمی‌شد».
راه‌حل نهایی کوچک‌سازی آیکون اصلی بود:

| عنصر | قبل | بعد |
|---|---|---|
| سلول جدول تزئینی ۳×۳ | 48dp | **36dp** |
| فاصلهٔ سلول‌ها | 6dp | **4dp** |
| پدینگ کادر | 20dp | **14dp** |
| فونت اعداد | پیش‌فرض | **15sp** |

جمع عرض کادر: ~۱۹۶dp → ~۱۴۴dp (۲۷٪ کوچک‌تر) و بنر بدون اسکرول دیده می‌شود.

**اصل:** تبلیغ نباید از دید خارج شود؛ اگر لازم شد، عناصر تزئینی اپ کوچک شوند.

## ۳.۷ حالت بدون تبلیغ — AdSlot

وقتی `ADS_ENABLED=false` یا در حالت Hidden، اگر اپ خواست جایگاه را حفظ کند، `AdSlot(slotHeight)`
کادری خط‌چین با متن «جایگاه تبلیغ» نشان می‌دهد — فقط برای دیباگ/پیش‌نمایش؛ در production
Hidden یعنی هیچ (اصل سکوت کامل).
