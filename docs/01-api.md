# ۱. قرارداد API — سرور تبلیغ

> مرجع رسمی: [`tabligh_icon.md`](tabligh_icon.md) (English). این فایل خلاصهٔ عملیاتی + نکات اجراشده است.

## ۱.۱ نقطهٔ اتصال

```
BASE_URL = https://golestanjaber.ir

GET {BASE_URL}/api/v2/api.php?app=<slug>&only=icons[&key=<api_key>]
```

| پارامتر | الزامی؟ | توضیح |
|---|---|---|
| `app` | ✅ | اسلاگ اپ — در پنل تبلیغات (تب «اپ‌ها») ثبت می‌شود |
| `only=icons` | پیشنهاد | پاسخ سبکِ فقط-آیکون؛ اپ نمونه از همین استفاده می‌کند |
| `key` | اختیاری | فقط اگر پنل برای اپ کلید صادر کرده باشد |

**Timeout های انتخابی اپ:** connect = 10s، read = 15s — فراتر از آن یعنی سرور در دسترس نیست → Hidden.

## ۱.۲ پاسخ موفق (HTTP 200)

```jsonc
{
  "icons_ratio": "1:1",            // نسبت تصویر همهٔ آیکون‌ها — "1:1" یا "9:3"
  "icons_next_slot_in": 7200,      // ثانیه تا چرخش بعدی اسلات‌ها (زمان‌بندی سمت سرور)
  "icons_period_seconds": 7200,    // دورهٔ کلی چرخش
  "icons": [
    {
      "slot": 1,
      "title": "جدول بزرگسال",
      "description": "سودوکوی حرفه‌ای برای بزرگسالان",
      "image_url": "https://golestanjaber.ir/uploads/icons/ad1.png",
      "click_url": "https://golestanjaber.ir/api/v2/click.php?app=<slug>&slot=1",
      "download_url": "https://example.com/dl/app1.apk",
      "clicks": 142
    }
    // ...
  ]
}
```

### نکات فیلدها (از تجربهٔ واقعی)

| فیلد | قاعده |
|---|---|
| `image_url` | بدون آن نمایش بی‌معنی است → آیتم را **رد کن** |
| `click_url` | آدرس `click.php` — با تپ باز می‌شود؛ کلیک را ثبت و 302 می‌کند |
| `download_url` | ⛔ هرگز با تپ باز نمی‌شود — فقط از طریق ریدایرکت `click_url` |
| `title` | زیر آیکون نمایش داده می‌شود؛ اگر در پنل خالی باشد «؟؟؟؟» یا خالی می‌افتد — پر کردنش کار مالک پنل است، نه کد اپ |
| `clicks` | فقط اطلاعاتی؛ برای منطق اپ استفاده نمی‌شود |

## ۱.۳ خطاها — ⚠️ مهم‌ترین نکتهٔ کل API

سرور خطا را **با HTTP 200** و بدنهٔ JSON برمی‌گرداند:

```json
{ "error": "app_not_found" }
```

بنابراین:
- **تصمیم خطا با فیلد `error` است، نه کد HTTP.** (`resp.code` چک نکن!)
- هر `error != null` → بنر مخفی (Hidden) + retry طبق جدول ۱.۵.
- خطاهای شناخته‌شده: `app_not_found` (اسلاک غلط)، `key_required` / `key_invalid`، `rate_limited`.

## ۱.۴ سازگاری فرمت جدید/قدیم سرور

سرور یک بار ارتقا خورد؛ اپ باید هر دو فرمت را بخواند (کد واقعی در `AdManager.kt::parseIcons`):

| مفهوم | فرمت جدید | فرمت قدیمی |
|---|---|---|
| نسبت تصویر | `icons_ratio` | `ratio` |
| ثانیه تا چرخش بعدی | `icons_next_slot_in` | `next_slot_in` |
| دورهٔ چرخش | `icons_period_seconds` | `period_seconds` |
| لیست آیکون‌ها | آرایهٔ `icons[]` | فیلدهای تکی سطح بالا (`image_url`, `click_url`, ...) |

برای فرمت قدیمی: فیلدهای تکی سطح‌بالا را به‌عنوان «یک آیتم» بپذیر (`target_url` هم مثل `download_url`).

## ۱.۵ سیاست retry سمت اپ (نتیجهٔ یک باگ واقعی!)

| وضعیت پاسخ | فاصله تا fetch بعدی | چرا |
|---|---|---|
| خطای ترنسپورت (بدون پاسخ) | **۵ دقیقه** | شاید اینترنت کاربر قطع است |
| `error` API | **۱۵ دقیقه** | مشکل پیکربندی است؛ فشار دادن بی‌فایده |
| موفق ولی `icons` خالی | **۲ دقیقه** ⭐ | مالک شاید همین الان در پنل آیکون فعال کند |
| موفق و پر | `max(60s, icons_next_slot_in)` | احترام به زمان‌بندی سرور؛ حداکثر یک fetch در دوره |

⭐ ردیف سوم نتیجهٔ باگ «هیچ تبلیغی نمایش داده نمی‌شود» بود: کد قدیمی برای حالت خالی هم کل
`next_slot_in` (~۲ ساعت) صبر می‌کرد و بنر تا ساعت‌ها برنمی‌گشت.

## ۱.۶ ثبت کلیک — `click.php`

```
GET {BASE_URL}/api/v2/click.php?app=<slug>&slot=<n>
→ شمارش کلیک در DB + 302 به download_url
```

- اپ فقط `click_url` را با `Intent.ACTION_VIEW` به مرورگر می‌سپارد — نه WebView، نه fetch داخل اپ.
- User-Agent برنامکی (مثل curl) دنبال‌کنندهٔ ریدایرکت است ولی کلیک **شمرده نمی‌شود** (فیلتر ربات)
  → برای تست بدون آلودن آمار عالی است.
